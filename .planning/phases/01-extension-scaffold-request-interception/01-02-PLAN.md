Add DPoP token handling to the existing content.js. This is the highest-risk piece — the strategy must handle the timing problem: we patch fetch at document_start (before app loads), but the app's DPoP wrapper only exists after app initialization.

**Strategy (two-phase capture):**

1. **Capture the app's wrapped fetch after app initializes.** After our initial monkey-patch runs at document_start, the Angular app will later overwrite window.fetch with its own version that adds DPoP headers. We need to detect this.

   Add a MutationObserver or polling mechanism that watches for the app to initialize. Approach:
   ```js
   let appFetch = null;

   // Poll for app's fetch wrapper (Angular overwrites window.fetch after bootstrap)
   const detectAppFetch = setInterval(() => {
     // Our patch is the outer layer. If the app re-wrapped, we need to capture it.
     // Check if the app has bootstrapped (e.g., document.querySelector('app-root') exists)
     if (document.querySelector('app-root, [ng-version]')) {
       // The current window.fetch is our wrapper around the app's wrapper around originalFetch
       // We need the "inner" fetch that the app set up — but we can't easily unwrap.
       // Instead: capture a reference to fetch as-is when app triggers a request.
       log('App detected as initialized');
       clearInterval(detectAppFetch);
     }
   }, 500);
   ```

   **Better approach — intercept-and-capture:** When we see the FIRST successful target request come through our fetch wrapper, capture the headers from that request (specifically the Authorization and DPoP headers). This gives us:
   - The Bearer token (from Authorization header)
   - A DPoP token example (to understand format)
   - Proof the app's auth chain is working

   In our fetch wrapper, when `isTargetRequest(url)`:
   ```js
   // Capture auth headers from the first real request
   if (!capturedAuth && init?.headers) {
     const headers = new Headers(init.headers);
     capturedAuth = {
       authorization: headers.get('authorization'),
       dpopKey: null, // Will extract from app
     };
     log('Captured auth headers from app request');
   }
   ```

2. **DPoP generation — Primary approach (DPOP-01): Use app's fetch for sub-requests.**

   Instead of generating DPoP ourselves, make sub-requests by calling through the app's fetch pipeline. After the app has initialized, `window.fetch` (from the app's perspective) includes its DPoP interceptor. We saved `originalFetch` which bypasses it. But if we instead create a NEW fetch call that goes through the app's interceptor chain:

   ```js
   // appWrappedFetch: a reference to fetch AFTER app has patched it
   // We capture this by re-reading window.fetch's inner function
   ```

   **Implementation:** Modify our fetch wrapper to save a reference to the "next" fetch in the chain. When our wrapper calls `originalFetch(input, init)`, that's the raw browser fetch. But the app puts ITS wrapper between our wrapper and the browser. So actually, the call chain is:
   - Our wrapper → app's wrapper → browser fetch

   Wait — this depends on load order. At `document_start`, we save `originalFetch = window.fetch` (browser's native). Then we set `window.fetch = ourWrapper`. Later, Angular bootstraps and does `const savedFetch = window.fetch` (which is ourWrapper) then `window.fetch = angularWrapper(savedFetch)`.

   So the chain becomes: angularWrapper → ourWrapper → originalFetch(native).

   This means our wrapper's `originalFetch` IS the native fetch, bypassing Angular's DPoP. But calls coming INTO our wrapper come FROM Angular's wrapper (which already added DPoP headers).

   **Key insight:** For INTERCEPTED requests (app-initiated), DPoP headers are ALREADY PRESENT because Angular added them before our wrapper sees the request. For OUR sub-requests, we need to go through Angular's wrapper.

   **Solution:** After Angular bootstraps, capture Angular's wrapper:
   ```js
   let angularFetch = null;

   // In our wrapper, detect when we're being called by Angular's wrapper
   // by checking if DPoP header is present
   window.fetch = async function(input, init) {
     const url = (input instanceof Request) ? input.url : String(input);
     const headers = new Headers(init?.headers || {});

     if (isTargetRequest(url) && headers.has('dpop') && !angularFetch) {
       // This request came through Angular's pipeline (has DPoP)
       // Capture: calling window.fetch from here would loop, but we can
       // save a "make-request-like-angular" function
       angularFetch = async (customUrl, customInit) => {
         // Clone the auth pattern from a real request
         // We'll build this after capturing the crypto key
       };
       log('Angular DPoP pipeline detected');
     }

     if (isTargetRequest(url)) {
       const range = parseDateRange(url);
       log('Intercepted fetch:', url);
       log('Date range:', range);
       // existing interception logic...
     }
     return originalFetch(input, init);
   };
   ```

3. **DPoP generation — Fallback approach (DPOP-02): Manual ES256 signing.**

   If we can't use Angular's pipeline for sub-requests, extract the CryptoKey and sign DPoP JWTs manually.

   Add a `DPoPSigner` class:
   ```js
   class DPoPSigner {
     constructor() {
       this.keyPair = null;
       this.jwk = null;
     }

     // Extract from observed DPoP JWT header
     async extractFromToken(dpopToken) {
       const [headerB64] = dpopToken.split('.');
       const header = JSON.parse(atob(headerB64.replace(/-/g,'+').replace(/_/g,'/')));
       this.jwk = header.jwk;
       // Import the public key to verify we can work with it
       // But we need the PRIVATE key to sign — we must find it in the app
       log('Extracted JWK from DPoP header:', this.jwk);
     }

     // Attempt to find the app's CryptoKey in memory
     async findCryptoKey() {
       // Hook crypto.subtle.sign to capture the key when app uses it
       const originalSign = crypto.subtle.sign.bind(crypto.subtle);
       crypto.subtle.sign = async function(algorithm, key, data) {
         if (algorithm?.name === 'ECDSA' || algorithm?.namedCurve === 'P-256') {
           log('Captured CryptoKey from app signing operation');
           this.keyPair = { privateKey: key };
           // Restore original to avoid overhead
           crypto.subtle.sign = originalSign;
         }
         return originalSign(algorithm, key, data);
       }.bind(this);
     }

     // Generate a DPoP JWT for a given method + URL
     async generateDPoP(method, url) {
       if (!this.keyPair?.privateKey) {
         throw new Error('No CryptoKey captured yet');
       }

       const header = {
         typ: 'dpop+jwt',
         alg: 'ES256',
         jwk: this.jwk
       };

       const payload = {
         htm: method,
         htu: url.split('?')[0], // URL without query string
         iat: Math.floor(Date.now() / 1000),
         jti: crypto.randomUUID()
       };

       const enc = new TextEncoder();
       const headerB64 = btoa(JSON.stringify(header)).replace(/=/g,'').replace(/\+/g,'-').replace(/\//g,'_');
       const payloadB64 = btoa(JSON.stringify(payload)).replace(/=/g,'').replace(/\+/g,'-').replace(/\//g,'_');
       const signingInput = enc.encode(`${headerB64}.${payloadB64}`);

       const signature = await crypto.subtle.sign(
         { name: 'ECDSA', hash: 'SHA-256' },
         this.keyPair.privateKey,
         signingInput
       );

       const sigB64 = btoa(String.fromCharCode(...new Uint8Array(signature)))
         .replace(/=/g,'').replace(/\+/g,'-').replace(/\//g,'_');

       return `${headerB64}.${payloadB64}.${sigB64}`;
     }
   }
   ```

4. **Integrate DPoPSigner into the fetch wrapper:**
   - Create global `const dpopSigner = new DPoPSigner();`
   - In fetch wrapper, when first DPoP-bearing request is seen, call `dpopSigner.extractFromToken(dpopHeader)` and `dpopSigner.findCryptoKey()`
   - Hook `crypto.subtle.sign` early (at script load, before `findCryptoKey` is called by a request) to capture the private key on first app use

5. **Add proof sub-request function:**
   ```js
   async function makeProofRequest() {
     if (!capturedAuth?.authorization) {
       log('Cannot make proof request — no auth captured yet. Wait for app to make a request first.');
       return;
     }

     // Build a test URL with a small date range (last 7 days)
     const to = Date.now();
     const from = to - (7 * 24 * 60 * 60 * 1000);
     const testUrl = `https://my.pokercraft.com/api/session/list/Holdem?from=${from}&to=${to}&currency=USD`;

     log('Making proof sub-request:', testUrl);

     try {
       const dpopToken = await dpopSigner.generateDPoP('GET', testUrl);
       const response = await originalFetch(testUrl, {
         headers: {
           'authorization': capturedAuth.authorization,
           'dpop': dpopToken,
         }
       });

       log('Proof request status:', response.status);
       if (response.ok) {
         const data = await response.clone().text();
         log('Proof request succeeded! Response length:', data.length);
       } else {
         log('Proof request failed:', response.status, response.statusText);
       }
     } catch (err) {
       log('Proof request error:', err.message);
     }
   }

   // Expose for manual testing in DevTools console
   window.__pokercraftUnlocker = { makeProofRequest, dpopSigner, log };
   ```

6. **Hook crypto.subtle.sign at script load** (before anything else, right after saving originalFetch):
   ```js
   const originalCryptoSign = crypto.subtle.sign.bind(crypto.subtle);
   let capturedPrivateKey = null;
   crypto.subtle.sign = async function(algorithm, key, data) {
     if (!capturedPrivateKey && (algorithm?.name === 'ECDSA' || (typeof algorithm === 'object' && algorithm?.hash === 'SHA-256'))) {
       capturedPrivateKey = key;
       dpopSigner.keyPair = { privateKey: key };
       log('Captured ECDSA CryptoKey from app');
     }
     return originalCryptoSign(algorithm, key, data);
   };
   ```
   This replaces the `findCryptoKey()` method — we hook early and capture passively.

- The `makeProofRequest` function uses `originalFetch` (bypassing Angular) + our own DPoP token, proving we can generate valid auth independently
- All new logging uses the existing `log()` helper with `[Pokercraft Unlocker]` prefix
