<task type="auto">
  <name>Task 1: Add MutationObserver date picker unlock to content.js</name>
  <files>extension/content.js</files>
  <action>
Add a date picker unlock section to content.js, placed BEFORE the `// --- Init ---` comment at the bottom. The implementation must:

1. **Create `unlockDateCells(container)` function** that:
   - Queries all elements inside `container` that have `aria-disabled="true"` or a `disabled` attribute, scoped to calendar-related elements (look for elements inside `.mat-calendar`, `mat-calendar`, or elements with class containing `calendar`)
   - For each disabled cell: remove `aria-disabled` attribute, remove `disabled` attribute, remove CSS classes that contain `disabled` (e.g., `mat-calendar-body-disabled`)
   - Remove any inline `pointer-events: none` style
   - Log count of unlocked cells: `log('Unlocked ${count} date cells')`

2. **Create `patchDatePicker()` function** that:
   - Sets up a MutationObserver on `document.body` watching `{ childList: true, subtree: true }`
   - On each mutation batch, check if any added nodes contain or are a calendar overlay/popup (look for `mat-calendar`, `mat-datepicker-content`, `cdk-overlay-container`, or class containing `calendar`)
   - When a calendar element is detected, call `unlockDateCells()` on it
   - Also set up a secondary MutationObserver on the calendar element itself watching `{ childList: true, subtree: true, attributes: true, attributeFilter: ['aria-disabled', 'class', 'disabled'] }` — this catches month navigation within the calendar which re-renders cells
   - Disconnect the secondary observer when the calendar overlay is removed from DOM

3. **Call `patchDatePicker()` at load time** (in the Init section)

4. **Update the init log** to: `log('Content script loaded — fetch/XHR interception active, DPoP capture enabled, date picker unlock active')`

5. **Add to window.__pokercraftUnlocker** the `patchDatePicker` function for debug access

Per user decision: Use DOM-level patching (not Angular config override) for resilience against app updates. MutationObserver MUST survive SPA navigation — since the observer is on document.body, it naturally persists across Angular route changes and will catch any new calendar popup.

IMPORTANT: If simply removing disabled attributes doesn't trigger Angular's click handling, also try dispatching a synthetic `MouseEvent('click', { bubbles: true })` — but first test without it, as Angular Material typically binds click on the cell element itself and removing disabled should suffice.
