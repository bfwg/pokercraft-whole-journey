  <name>Task 1: Add chunking engine and response merging to content.js</name>

  <action>
Add three new functions to extension/content.js (insert between the makeProofRequest function and the `window.__pokercraftUnlocker` line):

**1. `splitDateRange(fromMs, toMs, chunkDays = 25)`**
- Takes from/to as millisecond timestamps (numbers), returns array of `{ from: number, to: number }` chunks
- Each chunk spans at most `chunkDays` days (25 * 24 * 60 * 60 * 1000 ms)
- Last chunk's `to` equals original `toMs` exactly (don't overshoot)
- Edge case: if range <= chunkDays, return single chunk (original range)

**2. `async fetchChunks(baseUrl, chunks)`**
- Takes the original URL string and chunk array from splitDateRange
- For each chunk sequentially (NOT parallel — to avoid rate limiting):
  - Build chunk URL by replacing `from` and `to` query params with chunk values
  - Generate fresh DPoP token via `dpopSigner.generateDPoP('GET', chunkUrl)`
  - Call `originalFetch(chunkUrl, { headers: { authorization: capturedAuth.authorization, dpop: dpopToken } })`
  - Parse response as JSON
  - Log progress: `[Pokercraft Unlocker] Chunk {i+1}/{total}: {chunkFrom} → {chunkTo} — {response.sessionIds?.length || 0} sessions`
  - If response.status !== 200, log error and skip that chunk (don't abort entire operation)
  - Add small delay between chunks: `await new Promise(r => setTimeout(r, 300))`
- Return array of parsed JSON response objects (successful ones only)

**3. `mergeResponses(responses, originalFromMs, originalToMs)`**
- Takes array of API response objects and the original from/to timestamps
- Each response object has shape: `{ sessionIds: [...], fromTime: number, toTime: number, remain: number, ... }`
- Merge all `sessionIds` arrays, deduplicate by value (they're string IDs)
- Set `fromTime` to `originalFromMs`, `toTime` to `originalToMs`
- Set `remain` to `0` (tells app there are no more pages)
- Preserve any other top-level fields from the first response
- Return the merged response object
- Log: `[Pokercraft Unlocker] Merged: {totalSessions} sessions from {chunks} chunks`

**4. Modify XHR send interceptor** to use chunking for large ranges:

In the `XMLHttpRequest.prototype.send` override, when `isLargeRange(range.days)` is true:
- Instead of logging "will need chunking (Phase 2)" and passing through, DO the chunking:
- Check `capturedAuth` exists — if not, log warning and pass through (can't chunk without auth)
- Parse from/to as milliseconds from URL: `Number(parsed.searchParams.get('from'))`, `Number(parsed.searchParams.get('to'))`
- Call `splitDateRange(fromMs, toMs)`
- Log: `[Pokercraft Unlocker] Splitting ${range.days}-day range into ${chunks.length} chunks`
- Call `fetchChunks(this._pcUrl, chunks)`
- Call `mergeResponses(responses, fromMs, toMs)`
- Create synthetic XHR response by overriding the XHR's response properties:
  ```javascript
  const mergedJson = JSON.stringify(merged);
  Object.defineProperty(this, 'readyState', { get: () => 4 });
  Object.defineProperty(this, 'status', { get: () => 200 });
  Object.defineProperty(this, 'statusText', { get: () => 'OK' });
  Object.defineProperty(this, 'responseText', { get: () => mergedJson });
  Object.defineProperty(this, 'response', { get: () => mergedJson });
  // Fire readystatechange and load events
  this.dispatchEvent(new Event('readystatechange'));
  this.dispatchEvent(new Event('load'));
  this.dispatchEvent(new Event('loadend'));
  ```
- Do NOT call `originalXHRSend` for the original request — we're replacing it entirely
- Return early (don't fall through to originalXHRSend.call)

**5. Also modify fetch interceptor** similarly for the fetch path (safety net):
- When `isLargeRange(range.days)` and `capturedAuth` exists:
  - Do the same chunking flow
  - Return `new Response(JSON.stringify(merged), { status: 200, headers: { 'content-type': 'application/json' } })`
  - Do NOT call `originalFetch` for the original request

**6. Update debug API:**
- Add `splitDateRange` and `mergeResponses` to `window.__pokercraftUnlocker` for testing

Important: Keep all existing code intact (interception, auth capture, DPoP). Only ADD the new functions and MODIFY the large-range branches in the interceptors.
