## Directory Purposes

**`.github/`:**
- Purpose: GitHub Actions and repository metadata
- Contains: Funding configuration
- Key files: `FUNDING.yml` (links to sponsorship)

**`.pw-harness/`:**
- Purpose: Playwright browser automation harness for testing and diagnostics
- Contains: Node.js scripts and dependencies for real-browser testing
- Key files:
  - `auth-probe.mjs` — Attempts to establish DPoP auth with real PokerCraft session
  - `diag.mjs` — Captures live request/response diagnostics
  - `extract-ls.mjs` — Extracts full session history for testing
- Committed: Yes, but not part of runtime extension (test infrastructure)

**`.planning/codebase/`:**
- Purpose: GSD (Get Stuff Done) orchestrator planning documents
- Contains: Markdown analysis documents (ARCHITECTURE.md, STRUCTURE.md, etc.)
- Key files: Generated by `/gsd-map-codebase` command; consumed by `/gsd-plan-phase` and `/gsd-execute-phase`

**`extension/`:**
- Purpose: Manifest V3 Chrome extension (the actual shipped artifact)
- Contains: Configuration and all runtime code
- Key files:
  - `manifest.json` — MV3 config specifying injection, permissions, icons
  - `content.js` — **The entire extension logic** (~900 lines, no dependencies)
  - `icons/` — 16x16, 48x48, 128x128 PNG extension icons

## Key File Locations

**Entry Points:**
- `extension/manifest.json` — Browser loads this; specifies `content.js` injection with `"world": "MAIN"` and `"run_at": "document_start"`
- `extension/content.js` (lines 1-6) — Saves original API references *first* before PokerCraft app code runs
- `extension/content.js` (lines 887-898) — Initialization entry point; waits for `document.body` then calls `patchDatePicker()`

**Configuration:**
- `extension/manifest.json` — Specifies:
  - Target domain: `https://my.pokercraft.com/*`
  - Execution world: `MAIN` (required for API hooking)
  - Run timing: `document_start` (required to capture originals)
  - Permissions: empty (intentional; no Chrome permissions needed)

**Core Logic:**
- `extension/content.js` — All logic in one file:
  - **Lines 1-6**: Save original API references
  - **Lines 8-25**: DPoP auth capture (crypto hook)
  - **Lines 29-87**: `DPoPSigner` class (JWT generation)
  - **Lines 133-190**: AES-CBC crypto utilities
  - **Lines 195-260**: Chunking engine
  - **Lines 262-282**: Response merge
  - **Lines 285-309**: Debug exports and utilities
  - **Lines 313-343**: Helper functions (isTargetRequest, parseDateRange, etc.)
  - **Lines 347-403**: Fetch interception hook
  - **Lines 408-517**: XHR interception hooks (open, send, setRequestHeader)
  - **Lines 542-825**: Date picker unlock (Angular component detection and patching)
  - **Lines 827-883**: Calendar MutationObserver and initialization
  - **Lines 887-898**: Script init (patchDatePicker on document.body)

**Testing:**
- `.pw-harness/auth-probe.mjs` — Manual test: verify DPoP token generation works
- `.pw-harness/extract-ls.mjs` — Manual test: extract sessions for range validation
- `.pw-harness/diag.mjs` — Manual diagnostic: capture request/response shapes for debugging

## Naming Conventions

**Files:**
- `content.js` — Single content script (MV3 naming)
- `manifest.json` — Standard MV3 manifest file
- `.mjs` — ES modules in test harness
- `icon*.png` — Icons named by pixel width (16, 48, 128)

**Directories:**
- `extension/` — Core extension assets
- `icons/` — Image assets
- `.pw-harness/` — Test infrastructure (dot-prefix convention)
- `.planning/codebase/` — Planning documents

**Functions:**
- `isTargetRequest()` — Predicate (is* prefix)
- `parseDateRange()` — Parser (parse* prefix)
- `splitDateRange()` — Splitter (split* prefix)
- `fetchChunks()` — Fetcher (fetch* prefix)
- `decryptResponse()` — Decryptor (decrypt* prefix)
- `encryptData()` — Encryptor (encrypt* prefix)
- `mergeResponses()` — Merger (merge* prefix)
- `unlockCalendar()` — Imperative (verb-noun)

**Variables:**
- `capturedAuth` — Past tense (captured, not capturing)
- `capturedPrivateKey` — Same pattern
- `lastHeaderA` — Last-seen value
- `dpopSigner` — Singleton object
- `originalFetch`, `originalXHRSend` — "original" prefix for saved APIs
- `_pcMethod`, `_pcUrl`, `_pcHeaders` — Underscore prefix for internal XHR state
- `_wasDisabled` — Marker flag on DOM element

**Types:**
- No TypeScript; vanilla JavaScript with JSDoc comments for complex functions
- Date ranges: milliseconds (Unix timestamp), e.g., `fromMs`, `toMs`
- API keys/tokens: string, stored on state objects (e.g., `capturedAuth = { authorization, ... }`)

## Where to Add New Code

**New Feature (e.g., new API endpoint interception):**
- Primary code: Add to `extension/content.js` in logical section:
  - Add predicate to `isTargetRequest()` (line 319-330) to match new endpoint
  - Add handler in fetch hook (line 347-403) or XHR hook (line 414-517)
  - Add logging: call `log()` with feature name (line 315-317 toggles DEBUG)
- Debug export: Add to `window.__pokercraftUnlocker` object (line 285) for manual testing in DevTools

**New Subsystem (e.g., request caching, response filtering):**
- Add to `extension/content.js` in dedicated section between existing subsystems
- Follow existing patterns:
  - Prefix state with subsystem name (e.g., `cached*`, `filtered*`)
  - Export debug helpers on `window.__pokercraftUnlocker`
  - Include logging via `log()` calls
- **Do not** create new files or extract to separate scripts (breaks MAIN world context)

**Utilities (e.g., new crypto function, new date helper):**
- Shared helpers: Add to `extension/content.js` with others (lines 313-343 for existing helpers)
- Crypto helpers: Add near `encryptData()` / `decryptResponse()` (lines 133-190)
- Date helpers: Add near `parseDateRange()` / `splitDateRange()` (lines 333-207)

**Testing & Diagnostics:**
- New manual test: Add `.mjs` file to `.pw-harness/` directory with Node.js-compatible code
- Diagnostic output: Save to `.pw-harness/*.json` for inspection
- Do not add Jest/Mocha tests (no test framework; headless automation impossible due to DPoP session binding)

## File Dependencies

**Critical load order:**
1. `extension/manifest.json` — Specifies when to inject `content.js`
2. `extension/content.js` (lines 1-6) — **Must run first** to save originals before PokerCraft app code

**No module imports or external dependencies:**
- `content.js` is standalone JavaScript; no `import`/`require` statements
- All APIs used are browser builtins: `fetch`, `XMLHttpRequest`, `crypto.subtle`, `TextEncoder`, `URL`, `MutationObserver`, `Event`, `ProgressEvent`
- No npm packages (by design; extension ships with zero dependencies)

**Optional test harness:**
- `.pw-harness/package.json` specifies Playwright and test utilities
- Not used at runtime (only for manual testing and diagnostics)
- Not included in shipped extension
