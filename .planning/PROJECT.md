# Pokercraft Date Range Unlocker

## What This Is

A Chrome extension that removes the 3-month date range restriction on Pokercraft's session history page. It patches the frontend date picker to allow arbitrary date ranges and transparently splits API requests into 25-day chunks to bypass the server-side limit, merging results before the app processes them.

## Core Value

Users can view and analyze their full poker session history across any time period, not just the last 3 months.

### Active

- [ ] Intercept `session/list/Holdem` API calls at the network layer (fetch/XHR)

- [ ] Each sub-request must use a valid DPoP token (generated by the app's own logic)

- [ ] Feed merged result back to the app transparently (app doesn't know about the splitting)

### Out of Scope

- Other game types besides Holdem — not needed currently
- Standalone Node.js tool — Chrome extension approach preferred
- Deobfuscating the entire main.js — only need to find and patch the date picker limit
- Server-side changes — working within existing API constraints

## Context

- Pokercraft (`my.pokercraft.com`) is GGPoker's hand history platform
- The frontend is an Angular app, heavily obfuscated (`main.94912d4608d7e262.js`, 3.6MB)
- API responses are AES-CBC encrypted (key from response header `a`, IV hardcoded)
- Existing `decode.js` in the project has the decryption logic for reference
- The API endpoint: `GET /api/session/list/Holdem?from={ts}&to={ts}&currency=USD`
- Auth: Bearer JWT + DPoP token (ES256, per-request, includes URL and timestamp)
- DPoP tokens are generated per-request by the app's internal crypto logic
- The frontend config has `sessionHands: { size: 0x4e20, month: 0x3 }` but it may be dead code
- The actual date picker restriction needs to be located in the obfuscated JS
- Cloudflare cookies (`__cf_bm`, `_cfuvid`) are present but managed by the browser

## Constraints

- **API limit**: Server rejects date ranges > ~3 months; must split into chunks <= 25 days
- **DPoP binding**: Each request needs a fresh DPoP token with the correct URL; must hook into the app's token generation
- **Obfuscation**: Main JS uses string array rotation obfuscation (`a30_0x5bf0()`); finding specific logic requires runtime analysis or static deobfuscation
- **Chrome Extension**: Must be Manifest V3 compatible
- **Auth tokens**: JWT expires (~6 hours based on iat/exp); extension operates within an active session
